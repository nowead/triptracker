# 차단기 트립 관리 안드로이드 앱 요구사항 정의서

## 적용 범위

| 항목 | 확정 내용 |
| --- | --- |
| 1차 플랫폼 | Android |
| 후속 확장 | iOS 지원 계획 |
| 데이터 사용 방식 | 한 기기에서 저장·조회 |
| 핵심 목적 | 차단기의 트립 횟수를 정확히 파악하여 교체 판단에 활용 |

## 1. 기능 목록

### 2026-09-28 분전함에서 차단기 추가 및 연동 검색

- 분전함 목록의 항목을 선택하거나 점 세 개 메뉴의 ‘차단기 추가’를 누르면 선택한 분전함을 부모로 지정한 차단기 등록 화면을 연다. 관·층·분전함을 자동 채우며 저장은 해당 분전함의 자식으로 수행한다.
- 차단기 등록·수정은 관 → 층 → 분전함 순서로 선택한다. 분전함 목록은 선택한 관·층에 속한 마스터만 표시한다. 관 변경 시 층·분전함, 층 변경 시 분전함을 해제한다. 저장 시 부모와 관·층 일치를 검증한다.
- 검색 필터의 분전함 목록도 입력 중인 관·층 조건에 맞춰 제한한다. 목록에서 선택한 분전함은 고유 ID로 정확히 조회한다. 분전함번호 부분 검색은 선택 창의 입력값으로 검색 기능으로 유지한다. 상위 조건이 바뀌면 기존 분전함 선택·번호 조건을 해제한다.
- 필터의 조회 버튼은 적용 후 필터를 자동으로 접고 결과를 표시한다. 모든 조회 메뉴에서 다시 펼쳐 수정할 수 있다. 건수조회의 관·층 필수값이 없으면 필터를 닫지 않고 안내한다.
- 적용된 조건은 결과 위에 한 번 표시한다. 차단기 목록의 각 행에서는 적용된 관·층을 생략하고, 분전함까지 정확히 선택했으면 분전함도 생략한다. 생략 여부는 입력 중인 조건이 아니라 적용된 조건으로 판단하며, 상세 보기·메뉴 접근성 설명은 전체 소속을 유지한다.

### 2026-09-27 SPARE 및 마스터 목록 개선

- 초기 마스터에서 원본 차단기번호가 SPARE 또는 SPARE(증설)인 87개를 제외한다. 분전함은 164개, 차단기는 171개다. 실제 사용 시 사용자가 등록한다.
- 이미 적재한 앱에서도 초기 원문 그대로이며 트립·추가 설치 구간이 없는 SPARE만 한 번 정리한다. 사용자가 수정·등록했거나 이력이 생긴 차단기는 보존한다. 초기 데이터 적용 기록은 유지한다.
- 분전함·차단기 마스터 목록은 간결한 행으로 표시하고 수정·삭제·설치 구간은 각 행의 점 세 개 메뉴에 둔다. 삭제 확인과 기존 삭제 제한은 유지한다.
- 목록은 번호, 소속, 위치/부하와 주요 사양 중심으로 표시한다. 긴 특기사항은 한 줄 요약하고 메뉴의 상세 보기에서 전체 내용을 확인한다. 검색 조건은 펼치고 접을 수 있게 하며 메뉴 터치 영역은 최소 48dp를 유지한다.

### 2026-09-27 초기 엑셀 데이터 확정 사항

- 사용자 제공 `차단기 트립 이력.xlsx`를 초기 데이터의 원본으로 사용한다. 파일 안의 사용법 안내는 데이터 처리 지시가 아니다.
- 원본의 관 `12`는 **2관**, `34`는 **3관**으로 변환한다. 공용 관을 새로 만들지 않는다.
- **1관에는 12층·13층이 실제로 존재한다.** 1관의 지상층 범위에 두 층을 추가하며 PH는 13층 다음으로 정렬한다. 다른 관의 허용 층 범위는 유지한다.
- `차단기마스터`의 `A-LE-B2 / E1~E10`에 기록된 PORT수 `20`은 `2P`의 오기이므로 포트 수 **2**로 정정한다.
- SPARE는 위 최신 기준에 따라 초기 등록에서 제외한다. 기존에 붙인 구분 번호는 구 버전 적재 자료를 식별하는 데만 사용하며 원문 출처는 보존한다.
- 가져온 원본의 빈 항목은 미입력 상태로 보존한다. 신규 수동 등록의 필수값 규칙은 유지한다. 기존 비고는 특기사항으로 유지한다.
- **분전함마스터·차단기마스터 두 시트만 사용한다.** 1관·2관·3관·4관·기타의 과거 이력과 사용법 시트는 가져오지 않는다. 이력 연결 규칙이나 확인 대기 기능은 필요 없다.
- 초기 분전함은 원본 165행 중 같은 관·층·번호의 중복 한 건을 합쳐 164개로 구성한다. 중복 행의 비어 있지 않은 위치는 보존하고, FROM분전함은 특기사항에 이름을 붙여 보존한다. 차단기번호가 있는 원본 258행 중 SPARE 87행을 제외한 171행을 등록한다.
- 각 초기 차단기는 원본 설치일자 또는 미상의 최초 설치 구간을 가지며 트립 0건으로 시작한다. 기존 앱 데이터가 있으면 동일 마스터는 기존 값을 유지하고 없는 마스터만 추가한다. 기존 이력·설치 구간은 변경하지 않는다.
- 초기 데이터 적용은 DB 트랜잭션으로 한 번만 수행한다. 앱을 다시 열거나 업데이트해도 사용자가 수정·삭제한 초기 데이터가 복원되지 않는다. 원본 시트·행·명칭은 동봉한 마스터 자료에 보존한다.

### 2026-09-27 화면 개편 확정 사항 (기존 화면·입력 규칙보다 우선)

목적은 분전함과 차단기 트립 이력의 관리 편의 향상이다. 다음 여섯 화면을 제공한다.

| 화면 | 필드 및 동작 |
| --- | --- |
| 분전함 마스터 | 관, 층, 분전함번호, 분전함위치, 특기사항. 생성·조회·수정·삭제 |
| 차단기 마스터 | 소속 분전함, 차단기번호, 차단기 종류, port 수, 정격전류(A), 설치일자, 장소(부하), 특기사항. 생성·조회·수정·삭제 |
| 차단기 트립이력 | 관, 층, 분전함번호, 차단기번호, 설치일자, 트립일자, 트립장소, 트립사유, 특기사항. 생성·조회·수정·삭제 |
| Trip 건수 조회 | 관·층 필수, 분전함번호·차단기번호 선택. 관, 층, 분전함번호, 차단기번호, 설치일자, 트립건수 표시. 현재/이전/전체 구간 선택 유지 |
| Trip 이력 상세 | 집계 행 선택 시 해당 설치 구간의 관·층·분전함번호·차단기번호·설치일자 헤더 표시. 헤더 선택 시 트립일자·트립장소·트립사유 및 특기사항을 팝업 표시 |
| 차단기 위치 조회 | 마스터를 연결하여 장소(부하) 포함 검색. 관, 층, 분전함번호, 분전함위치, 차단기번호, 장소(부하) 표시 |

- 설치일자와 기존 교체일자는 같은 의미다. 차단기명은 차단기번호로 표시한다. 교체 후 새 구간은 0건부터 집계하며 이전 이력과 구간은 보존한다. 설치일 미상을 허용한다.
- 분전함을 먼저 등록하고 차단기를 등록한다. 트립 등록 시 기존 차단기와 설치 구간을 선택하여 식별 정보·설치일자를 자동 표시한다. 마스터만 등록해도 0건 조회가 가능하다.
- 소속 차단기가 있는 분전함, 트립 이력이 있는 차단기는 삭제를 제한한다. 삭제 전 대상과 건수를 확인한다.
- 종류는 직접 입력, port 수는 양의 정수, 정격전류는 양의 A 값(소수 허용)이다. 특기사항은 선택이고 그 밖의 입력 항목은 필수다. 설치일자는 날짜 또는 미상을 선택한다.
- 기존 데이터·고유 ID·설치 구간·횟수는 보존한다. 기존 비고는 트립 이력의 특기사항이며 트립사유로 전환하지 않는다. 새 필드의 기존 값은 미입력으로 표시하고 수정 시 보완한다. 기존 트립장소를 마스터의 장소(부하)로 추정하지 않는다.
- 반복 입력 편의를 위해 저장된 종류·port 수·정격전류·분전함위치·장소(부하)·트립장소·트립사유를 중복 없는 선택 목록으로 제공한다. 직접 새 값을 입력할 수 있고 저장 성공 후 목록에 자동 반영한다. 기기 재실행 후에도 저장 데이터에서 목록을 복원한다.
- 관·층의 기존 범위, 문자열 정규화, 같은 날 다회 트립, 날짜 검증, 구간 정정·삭제 규칙은 유지한다. 포함 검색에서 %, _는 문자 그대로 검색한다.
- 횟수 조회의 관·층이 없으면 결과 대신 필수 조건 안내를 표시한다. 마스터·트립 목록 및 위치 조회는 전체 목록에서 시작할 수 있다.

아래 최초 트립과 차단기 동시 생성, 횟수 조회의 관·층 선택 입력, 기존 현황 중심 첫 화면은 이번 개편으로 대체한다. 첫 화면은 분전함 마스터이며 주요 메뉴는 분전함·차단기·트립이력·건수조회·위치조회다.

| 기능 | 설명 |
| --- | --- |
| 등록 | 차단기 트립 이력을 등록한다. |
| 수정 | 조건에 맞는 이력을 조회하고 선택한 이력을 수정한다. |
| 삭제 | 조건에 맞는 이력을 조회하고 하나 또는 여러 이력을 선택하여 삭제한다. |
| 조회 (상세) | 입력한 조건에 해당하는 트립 이력의 상세 내용을 조회한다. |
| 조회 (횟수) | 입력한 조건에 해당하는 차단기의 트립 횟수를 조회한다. |

## 2. 등록 항목 및 입력 규칙

| 항목 | 입력 방식 및 규칙 | 검색 기준 포함 여부 |
| --- | --- | --- |
| 관 | 1~4 중 선택 | 포함 |
| 층 | B1~B5, 1~11, PH 중 선택. 1관은 12·13층도 허용 | 포함 |
| 분전함번호 | 대문자 입력 | 포함 |
| 차단기명 | 대문자 입력 | 포함 |
| 장소 | 대문자 입력 | 미포함 |
| 트립일자 | 오늘 날짜를 기본으로 표시하며, 필요시 캘린더로 변경 가능 | 포함 |
| 교체일자 | 선택한 교체 구간의 교체일자를 표시한다. 최초 등록 시 캘린더로 입력하거나, 마지막 교체일자를 모르면 ‘교체일 미상’을 선택할 수 있다. | 미포함 |
| 교체 구간 | 새 트립 등록 시 해당 차단기의 현재 구간을 기본 선택한다. 과거 트립 입력 시 이전 구간을 선택할 수 있다. | 미포함 |
| 비고 | 비고 입력 | 미포함 |

| 구분 | 정의 |
| --- | --- |
| 기존 복합 Key의 역할 | 관 + 층 + 분전함번호 + 차단기명 + 트립일자는 검색 기준이며, 이 조합에 유일성 제약을 두지 않는다. |
| 개별 이력 식별 | 시스템이 각 이력에 고유한 내부 ID를 부여한다. 사용자가 별도로 입력하지 않는다. |
| 동일 날짜 다회 트립 | 같은 차단기가 같은 날 두 번 트립하면 별도 이력 두 건으로 저장한다. 입력 항목이 같아도 서로 다른 발생 건이면 허용한다. |
| 횟수 계산 단위 | 실제 트립 발생 1건을 1회로 집계한다. 날짜별로 합치거나 중복 제거하지 않는다. |
| 교체 후 집계 | 차단기를 교체하면 새 교체 구간의 트립 횟수를 0회부터 시작한다. 교체 자체는 트립 횟수에 포함하지 않는다. |
| 교체 전 이력 | 이전 교체 구간의 트립 이력과 횟수를 보존하고 별도로 조회할 수 있다. 교체를 이유로 기존 이력을 삭제하거나 새 구간으로 옮기지 않는다. |
| 집계 범위 | 같은 차단기라도 교체 구간별로 발생 건수를 따로 집계한다. 새 구간에서 트립하면 해당 구간의 횟수만 증가한다. |
| 교체일 미상 | 마지막 교체일자를 모르는 차단기도 최초 구간을 만들고 트립을 등록할 수 있다. 임의 날짜를 대신 저장하지 않는다. |
| 미상 구간의 횟수 | 해당 구간에 기록한 트립 건수를 집계한다. 날짜가 없다는 이유로 조회·집계에서 제외하거나 다른 차단기의 미상 구간과 합치지 않는다. |
| 미상 구간 이후 교체 | 실제 교체 등록 시 새 구간은 0회로 시작하고, 이전 미상 구간의 이력과 횟수를 보존한다. |
| 등록 시 구간 연결 | 트립은 사용자가 확인한 선택 구간에 저장한다. 과거 트립을 이전 구간에 등록하면 이전 구간 횟수만 증가하며 현재 구간 횟수는 유지된다. |
| 교체 당일 입력 | 교체 전후 트립의 날짜가 같아도 해당 구간을 선택하여 구분한다. 날짜만으로 두 구간의 이력을 합치지 않는다. |
| 수정·삭제 대상 | 검색 결과에서 선택한 개별 이력 ID를 기준으로 처리한다. 같은 검색 조건의 다른 이력에 영향을 주지 않는다. |
| 최초 등록 절차 | 별도 차단기 사전 등록 없이 첫 트립 화면에서 차단기 정보·마지막 교체일자 또는 미상·트립 정보를 입력한다. 저장 한 번으로 차단기·최초 구간·트립 1건을 함께 생성하고 1회로 집계한다. |
| 최초 저장 원자성 | 저장 실패 시 차단기·구간·트립의 일부만 남기지 않는다. 이미 등록된 차단기는 기존 구간을 선택하여 트립만 추가한다. |

### 교체 기록 정정·삭제 및 날짜 검증

| 항목 | 확정 규칙 |
| --- | --- |
| 교체일 정정 | 같은 구간의 날짜만 수정한다. 구간 ID, 연결된 트립, 횟수, 현재·이전 상태를 유지한다. |
| 미상 날짜 보완 | 나중에 교체일자를 알게 되면 기존 미상 구간에 날짜를 입력한다. 새 구간을 만들거나 횟수를 초기화하지 않는다. |
| 트립이 있는 구간 삭제 | 삭제를 제한한다. 잘못 연결한 트립은 수정에서 올바른 구간으로 먼저 옮긴다. 구간과 함께 트립을 일괄 삭제하지 않는다. |
| 트립의 구간 정정 | 개별 트립 ID와 전체 건수를 유지하며 원래 구간은 1회 감소, 대상 구간은 1회 증가한다. |
| 빈 과거 구간 삭제 | 대상 확인 후 삭제하며 다른 구간과 트립을 유지한다. |
| 빈 현재 구간 삭제 | 이전 구간이 있으면 복원될 구간과 횟수를 안내하고 확인 후 삭제한다. 직전 구간을 현재로 복원한다. |
| 유일한 구간 삭제 | 차단기에 남은 유일한 구간은 삭제를 제한한다. 날짜 오류는 정정으로 처리한다. |
| 날짜 불일치 | 오류 내용을 안내하고 저장을 제한한다. 날짜 정정만으로 트립을 자동 이동하지 않는다. |
| 트립 날짜 범위 | 알려진 구간 시작일 이상, 다음 구간 시작일 이하를 허용한다. 경계일은 전후 구간 모두 선택할 수 있다. |
| 교체 날짜 순서 | 구간 순서대로 알려진 교체일이 감소하지 않아야 한다. 같은 날 여러 교체 구간은 허용한다. |
| 미상 날짜 검증 | 알 수 없는 시작일을 추정하지 않고 확인 가능한 날짜 경계만 검사한다. |
| 정정 영향 검증 | 수정한 날짜가 대상 구간과 영향을 받는 인접 구간의 기존 트립에 모순을 만들면 저장을 제한한다. |
| 미래 날짜 | 기기 현지 오늘 날짜보다 미래인 트립일자·교체일자는 저장을 제한한다. |

예: 이전 구간 3회·잘못 등록한 현재 구간 0회에서 빈 현재 구간을 삭제하면, 직전 구간이 현재 3회로 복원된다. 이는 실제 교체 등록과 다른 정정 동작이다.

### 검색 조건 및 동작

수정·삭제 대상 검색과 상세 조회는 같은 규칙을 사용한다. 등록 필수값은 검색 필수값이 아니다.

| 조건 | 상세 조회·수정·삭제 | 횟수 조회 | 일치 방식 |
| --- | --- | --- | --- |
| 관 | 선택 입력 | 선택 입력 | 전체 또는 1~4, 정확히 일치 |
| 층 | 선택 입력 | 선택 입력 | 전체 또는 지정 층, 정확히 일치 |
| 분전함번호 | 선택 입력 | 선택 입력 | 대소문자 구분 없이 포함 검색 |
| 차단기명 | 선택 입력 | 선택 입력 | 대소문자 구분 없이 포함 검색. R1은 R10에도 일치 |
| 트립일자 | 선택 입력 | 사용하지 않음 | 기본 전체 날짜, 날짜 하나 선택 시 해당 하루 조회 |
| 교체 구간 범위 | 전체 구간 | 현재 / 이전 / 전체 선택 | 횟수 조회의 기본값은 현재 |

| 동작 | 확정 규칙 |
| --- | --- |
| 조건 조합 | 입력한 조건을 모두 만족하는 결과를 조회한다(AND). 빈 조건은 제한하지 않는다. |
| 조건 없는 조회 | 상세 조회는 전체 트립, 횟수 조회는 선택한 구간 범위의 전체 구간을 표시한다. |
| 첫 진입 | 기본 조건으로 결과를 표시한다. |

| 선택 해제 | 다른 조건으로 다시 조회하면 기존 삭제 대상 선택을 해제한다. |

## 4. 조회 결과 항목

### 2026-09-27 시각 디자인 개선

시인성·정돈된 디자인·적당한 여백을 우선한다. 짙은 본문과 보조 정보의 대비를 확보하고, 검색·결과·입력 영역을 구분한다. 화면 및 카드 안쪽 20dp, 주요 입력 간 16dp를 기본 간격으로 사용한다. 한글 산세리프 글꼴과 충분한 행간을 적용하며 큰 글자 설정에서도 필드와 버튼을 스크롤해 이용할 수 있어야 한다. 색상·아이콘·글자 굵기는 정보의 위계를 보조하며 업무 규칙과 표시 항목은 유지한다.

### 메인 화면 및 디자인

| 항목 | 확정 내용 |

| 조회 구분 | 표시 항목 |
| --- | --- |
| 조회 (상세) | 관, 층, 분전함번호, 차단기명, 장소, 트립일자, 교체일자, 비고, 이력번호, 등록시각 |

횟수는 교체 구간별로 표시하며 현재 / 이전 / 전체 범위를 선택할 수 있다. 기본은 현재 구간이며, 교체 직후 트립 이력이 없는 현재 구간도 0회로 표시한다.

교체일자를 모르는 구간은 상세 조회·횟수 조회·구간 선택에서 ‘교체일 미상’으로 표시한다. 횟수는 앱에 기록한 발생 건수이며, 기록되지 않은 과거 트립 횟수를 추정하지 않는다.

| 표시 항목 | 확정 규칙 |
| --- | --- |
| 상세 목록 | 차단기 식별 정보·장소·트립일자·교체일자 또는 미상·이력번호 표시. 전체 항목은 상세 화면에서 확인한다. |
| 이력번호·등록시각 | 같은 날 같은 값의 이력도 고유 번호로 구분한다. 번호는 정렬·삭제 후에도 유지하며, 등록시각은 실제 트립 발생시각과 구분한다. |
| 횟수 조회 장소 | 해당 구간의 가장 최근 트립일자 이력에서 가져온다. 같은 날짜면 등록시각·이력 ID 순으로 결정한다. 트립 0건이면 ‘—’로 표시한다. |
| 결과 건수 | 상세 조회는 트립 이력 건수, 횟수 조회는 집계 구간 수로 표시한다. |

### 기본 정렬

| 화면 | 정렬 기준 |
| --- | --- |
| 상세 이력·수정·삭제 목록 | 트립일자 최신순 → 등록시각 최신순 → 고유 이력 ID의 고정 순서 |
| 횟수 조회 | 트립횟수 많은 순 → 관 오름차순 → 층 순서 → 분전함번호·차단기명 문자순 → 구간 순서 최신순 → 구간 ID |
| 구간 선택 | 현재 먼저, 이전 구간은 교체 순서 최신순. 같은 날짜는 구간 번호로 구분 |

층 순서는 B5 → B4 → B3 → B2 → B1 → 1 → … → 13 → PH다. 코드의 문자순 정렬에 숫자 자연 정렬을 적용하지 않는다. 미상 교체일을 구간 순서 기준으로 쓰지 않으며, 0회 구간도 횟수 정렬에 포함한다.

## 6. 원문 기준 확인 필요 사항

| 항목 | 확인이 필요한 내용 |
| --- | --- |
| 교체 등록 화면 | 교체 후 0회 시작, 과거 구간 보존, 교체 기록 정정·삭제 규칙은 확정했다. 새 교체 사실을 입력하는 화면의 구체적인 구성은 설계안 검토가 필요하다. |
| 교체 판단 기준 | 트립 횟수가 교체 판단에 중요하다는 목적은 확정했다. 특정 횟수에 따른 자동 경고나 교체 권고 기능은 아직 정의하지 않았다. |

> 최초 예시는 유지하고 사용자 확인 사항을 반영했다. 같은 날 다회 트립 허용은 원문의 복합 Key 유일성 해석보다 우선한다. 교체일자는 직전 입력 이력 대신 선택한 교체 구간에서 가져온다. 그 밖의 미확정 동작은 별도 확인한다.
